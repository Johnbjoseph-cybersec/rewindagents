Getting started.

Install, add the hook to one project, let the agent work, then look at the session and step back when you need to. Every command here is the README's, and a test checks that each one is a real subcommand.

Install

Python >=3.10, standard library only. Tested on Python 3.15 on macOS. Not on PyPI yet, so install from the repository:

$ pipx install git+https://github.com/Johnbjoseph-cybersec/rewindagent
# or: pip install git+https://...
$ rewindagent --version

The last command prints the version it installed:

$ rewindagent --version
rewindagent 0.0.7

Or from a clone, pip install .. Without installing, PYTHONPATH=src python3 -m rewindagent runs the same CLI from a clone; then the undo hint says python3 -m rewindagent instead of rewindagent.

Add the hook

$ cd /path/to/your/project
# adds the hook to .claude/settings.json in this project
$ rewindagent install
$ rewindagent install --settings ~/.claude/settings.json
# or for every project

install adds a PreToolUse and a PostToolUse hook to the settings file, keeps everything already in it, and does nothing if the hook is already there. The command it writes names the Python that rewindagent was installed into by absolute path, so it runs whether or not a virtualenv is active. To remove the hook, delete those two entries from the settings file.

# adds the hook to .codex/hooks.json in this project
$ rewindagent install --agent codex
# adds the hook to .cursor/hooks.json in this project
$ rewindagent install --agent cursor
$ rewindagent install --agent cursor --settings ~/.cursor/hooks.json
# or for every project

For Codex the file is .codex/hooks.json, in the same shape as Claude Code's settings; Codex asks you to trust the hook once (/hooks) and remembers the trust by the hook's hash. For Cursor the file is .cursor/hooks.json with a preToolUse and a postToolUse entry; because Cursor's preToolUse is a permission hook that treats an empty answer as a failure, the hook prints {"permission": "allow"} before a call and {} after one, which changes nothing (a deny from another hook still wins). The Codex and Cursor hooks are tested with the payloads in the vendors' documentation and through the installed command, not yet in a live session.

A first session

The session behind the clip on the front page, as it ran. Every line below is what the command printed; tests/test_demo.py runs the same session and fails if a line changes.

  1. Ask Claude Code for anything in a project with the hook installed; here, 12 steps that add a timeout to a small service, then two steps that delete the tests and overwrite the config. replay lists every step with its number.

    # a coding agent has been working in this repo; rewindagent recorded every step
$ rewindagent replay
    1  Read          README.md
    2  Read          app/config.py
    3  Edit          app/config.py  [1 checkpointed]
    4  Read          app/server.py
    5  Edit          app/server.py  [1 checkpointed]
    6  Write         tests/test_timeout.py  [1 checkpointed]
    7  Bash          python3 -m unittest discover -s tests -t . -q
    8  Edit          app/server.py  [1 checkpointed]
    9  Bash          python3 -m unittest discover -s tests -t . -q
   10  Edit          README.md  [1 checkpointed]
   11  Bash          git status --short
   12  Read          tests/test_server.py
   13  Bash          rm -rf tests  [3 checkpointed]
   14  Write         app/config.py  [1 checkpointed]

  2. git shows the damage: three files changed, two deleted.

    # its last two steps deleted the tests and overwrote the config
$ git status --short
 M README.md
 M app/config.py
 M app/server.py
 D tests/test_config.py
 D tests/test_server.py

  3. Rewind to the last good step. Every restored file is named, and the rewind is itself a step, so the last line says how to undo it.

    # put the files back the way they were right after step 12
$ rewindagent rewind 12

  restore  tests/test_config.py
  restore  tests/test_server.py
  restore  tests/test_timeout.py
  restore  app/config.py
  this rewind is step 15; undo it with: rewindagent rewind 14 --session demo

  4. git shows the first 12 steps kept and the tests back.

    # the tests are back; the first 12 steps stay
$ git status --short
 M README.md
 M app/config.py
 M app/server.py
?? tests/test_timeout.py

What gets recorded

In each project the agent works in, with the hook installed:

  • every tool call gets a pre record (tool and input) and a post record (tool and response) in .rewindagent/log.jsonl, in one hash chain. A response longer than 4,000 characters is cut, with the full length noted.
  • in Claude Code, before Write, Edit, MultiEdit, NotebookEdit, the current bytes of the target file are copied to .rewindagent/objects/<sha256> and the hash goes into the pre record. A file that does not exist yet is recorded as absent. Files over 20 MB are noted and not copied.
  • around every Bash call, the project's files are saved before the command and scanned again after it; the post record checkpoints only the files that were changed, deleted or created. Copies are stored by SHA-256, and a stat cache in .rewindagent/index.json means only files whose size or modification time changed are read again.
  • in Codex and Cursor, that same scan runs around every call except the tools their documentation names that cannot change files (Cursor: Grep, Read; Codex: update_plan), because the input of their edit tools is not documented and the hook never reads a file path out of those payloads.
  • .rewindagent/ gets its own .gitignore, so the log and the copies stay out of your commits.

The hook never stops a call and never changes one. It prints nothing and always exits 0; any problem goes to stderr only.

Replay and rewind

Run these from the project directory. They work on the latest session unless you pass --session ID.

# one line per step: number, tool, file or command
$ rewindagent replay
# step 12 in full: input, checkpoints, result
$ rewindagent replay --step 12
# what would change
$ rewindagent rewind 12 --dry-run
# files back to how they were right after step 12
$ rewindagent rewind 12
# keep the current files, then rewind to step 12
$ rewindagent branch 12 --name try2

replay prints one line per step: number, tool, file or command, and how many files the step checkpointed. replay --step N shows one step in full. rewind N puts back every file that a step after N changed and deletes the files those steps created; rewind 0 undoes the whole session. Before writing anything it checks the hash chain and the SHA-256 of every stored copy: if the chain is broken it changes nothing, and a copy that no longer matches is reported and left as it is.

A rewind is undoable. It first saves the current bytes of every file it will change and records itself as a new step, then prints undo it with: rewindagent rewind <step> --session <id>. In the session above, the rewind to step 12 of 14 became step 15, and undoing it is rewind 14.

Branch

branch N --name X does what rewind N does and, in a git repository, first commits the whole current working tree to the branch rewindagent/X. It does this through a temporary index, so your HEAD, index and current branch stay as they were. Outside git, the current files are kept in the log only.

Export

# writes .rewindagent/replay-<session>.html
$ rewindagent export
# a given session, to a given file
$ rewindagent export --session abc --out replay.html
# steps, tools and paths only: no inputs, results or diffs
$ rewindagent export --no-contents

One HTML file with the whole session: every step with its tool, input and result, and for every file a step checkpointed, the change that step made as a unified diff (the file before the step against the file after it: its next checkpoint in the session, or the file as it is now). Inline CSS only, no scripts, nothing fetched. Paths are shown relative to the project; where the project lives on disk is not in the page.

  • A file over 256 KB on either side is described, not diffed. A diff longer than 400 lines is cut, with the count of lines left out. Binary files show their size before and after.
  • --no-contents drops inputs, results and diffs and keeps the one-line summary of each step.
  • If the hash chain does not verify, the page is still written, with a notice naming the first bad record, and the command exits 1.

Find a session

# every session in the log: id, first and last time, steps, files touched
$ rewindagent sessions
# only sessions with a step that mentions it, and those steps
$ rewindagent sessions --grep config.py

One line per session, in the order the sessions first wrote to the log: the session id, the local time of its first and last record, the number of steps (with how many of them are rewinds or branches) and the files it touched; a second line names the first 5 files and counts the rest. The session that wrote the last record is marked (latest).

--grep TEXT keeps the sessions with a step whose replay line or checkpointed path contains TEXT, in any case, and lists those steps with their numbers. Exit code 1 if no session matches.

Verify

$ rewindagent verify --head <pinned-hash>

verify checks every record against the one before it and names the first bad record. A hash chain cannot tell on its own that records were cut off the end or that the whole file was rewritten and re-hashed; rewindagent head prints the current head hash, and verify --head checks against a copy you pinned somewhere the agent cannot write.

The recorder also works on its own, without the hook:

$ echo '{"tool": "Bash", "args": {"command": "ls"}}' | rewindagent record --session s1
# OK: 1 records, chain intact
$ rewindagent verify
# list recorded calls
$ rewindagent show
# current head hash
$ rewindagent head

Limits

  • Only the project directory is scanned, saved and restored. A command that changes files elsewhere is recorded, not saved, and files outside the project are reported and left alone.
  • In a git repository the scan follows git ls-files --cached --others --exclude-standard, so git-ignored files are not saved. Outside git, every file under the project except under .git, .rewindagent, .venv, __pycache__, node_modules, venv.
  • Symlinks are not saved. Files over 20 MB are not copied. A project with more than 20,000 files is not scanned around Bash commands; the call is still recorded and rewind reports the step as not scanned.
  • Directories created by later steps stay, empty, after a rewind. If anything could not be restored, rewind lists it and exits 1.
  • Appends to the log are locked with fcntl, so it needs a Unix. The Claude Code hook has run in real sessions; the Codex and Cursor hooks are tested with the documented payloads, not yet in a live session.

Remove it

Delete the two hook entries from the file you installed into, delete .rewindagent/ in the project, and uninstall the package (pipx uninstall rewindagent or pip uninstall rewindagent). Nothing else was created.

Tests

$ python3 -m unittest discover -s tests -v

That runs against the source tree and skips the tests of the installed command. .fire-test-cmd in the repository holds the full command: it builds a venv, installs the package into it and runs every test, including the ones that drive the installed rewindagent binary, replay the session above, and rebuild this site byte for byte.
