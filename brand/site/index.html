v1.2.0 hooks for 7 coding agents

Your coding agent ran rm -rf. Take it back.

Install. From PyPI; then add the hook in a project. One click on a command selects all of it, without the prompt.

$ pipx install rewindagents
# or: pip install rewindagents
# adds the hook to .claude/settings.json in this project
$ rewindagents install

rewindagents records every step your coding agent takes and saves each file before it changes, including files only a shell command touched. When a run goes wrong, take back the whole session, one step, or one file.

Then fork any recorded step, let another agent continue from there, and compare the runs, within the limits.

01The gap

What Claude Code's checkpoints miss.

Claude Code's own checkpointing docs name the gap this fills. rewindagents copies the project's files before every shell command and scans them after, so a sed -i or an rm is one more step you can rewind.

After your agent...Claude Code checkpointsrewindagents

  • had a subagent edit filesClaude Code checkpointsusually doesn't capture those edits docsrewindagentsrecorded through the same hooksA live session in which a subagent made eight steps, three of them edits, recorded and checkpointed all of them (ux-review/DOGFOOD.md).

03Fork and compare

Rewind to a step, fork it, compare.

Rewind to any step, fork it, let another agent take it from there, compare. A recorded step is a starting point you can hand to another agent, another model, another prompt or a person, and the runs that follow can be compared on what they actually did to the files and on your own check.

Fork any recorded step

rewindagents fork 12 --name try2 makes a new directory holding the project as rewind 12 would leave it. Run any agent there, or edit by hand.

# pick the step to start from, say 12
$ rewindagents replay
# ../<project>-try2 with step 12's files
$ rewindagents fork 12 --name try2
# run any agent with a hook here, or edit by hand
$ cd ../your-project-try2
$ cd - && rewindagents compare --check "python3 -m pytest -q"
# how two runs differ, as a git diff
$ rewindagents compare --diff your-project try2

A session, and a second try from step 2

What ux-review/try-runs.sh printed against an installed build, unedited; lines naming its temporary folder are left out. shop is the agent's run, recorded through the real hook; clamp is a second attempt made by hand in the fork.

$ rewindagents fork 2 --name clamp
  2 files as they were right after step 2 of session demo-0001; git worktree on branch rewindagents/run/clamp
$ rewindagents compare --check "python3 test_cart.py"

Compare the runs

rewindagents compare lines up the project and every run forked from the same step: files changed, lines added and removed. --check runs your own check in each run and reports pass or the exit code.

$ rewindagents compare --diff shop clamp
diff --git a/cart.py b/cart.py
--- a/cart.py
+++ b/cart.py
@@ -1,2 +1,2 @@
 def total(prices, discount=0):
-    return sum(prices) - discount  # TODO clamp
+    return max(0, sum(prices) - discount)

What it will not do

  • fork refuses a step it cannot rebuild exactly (a stored copy missing, a command whose scan did not finish, a log that does not verify) and leaves nothing behind when it fails half-way.
  • compare writes nothing; the command --check runs may write in the run it runs in.
  • Runs from different steps are not mixed.

Every option, and how a fork works in a git repository, is on the docs page.

04The timeline

The flight recorder for your coding agent.

See exactly what your agent did, step by step, with the diff each step made. Take back the whole session, one step, or one file, and preview the change before you make it.

One command to set up

init finds the agents you have and adds the hook to each one, keeping every hook already there.

$ pipx install rewindagents && cd your-project && rewindagents init

See it

The timeline in your browser: every step, every file, every diff. j k to move, r to rewind.

# opens the timeline in your browser; Ctrl+C stops it
$ rewindagents ui

Take back exactly what you mean

Preview a rewind as a diff, then take back the whole session or a single file. Every rewind is a new step, so it can be undone.

# what taking it back to step 12 would change
$ rewindagents diff 12
# take back just that file
$ rewindagents rewind 12 --only src/db.py

06How it works

Record. Checkpoint. Rewind.

A hook runs before and after every tool call the agent makes. It never stops a call and never changes one: it always exits 0, even when its own input is broken or the disk is full, and prints nothing but the one answer Cursor requires from a permission hook.

  1. Record

    Every call gets a pre record (tool and input) and a post record (tool and response) in .rewindagents/log.jsonl. Each record carries the SHA-256 of the one before it, so editing, deleting or reordering any record makes verify fail and name the first bad record. Appends are locked, so several processes can write to one log.

  2. Checkpoint

    Before Write, Edit, MultiEdit and NotebookEdit, the current bytes of the target file go to .rewindagents/objects/<sha256>. Around a Bash command, the project's files are saved first and scanned after, and only the files the command changed, created or deleted are checkpointed. Copies are stored by hash, so an unchanged file is stored once.

  3. Rewind

    rewind N puts back every file a later step changed and deletes the files later steps created. It first checks the hash chain and the hash of every stored copy; if the chain is broken it changes nothing. A rewind saves the current files and records itself as a new step, so a rewind is undone with another rewind.

08Limits

What it records, and where it stops.

The real behaviour and the real limit, from the code. rewind reports every file it could not put back and exits 1 if there was one.

  • 4,000 charactersA tool response longer than this is cut in the log, with its full length noted.
  • 20 MBA file over this size is noted and not copied, so it is reported and not restored.
  • 20,000 filesA project with more than this many files is not scanned around Bash commands. The call is still recorded, and rewind says the step was not scanned.
  • the project directoryOnly files inside it are scanned, saved or restored. In a git repository, the scan is what git ls-files --cached --others --exclude-standard lists: tracked and untracked files, not git-ignored ones. Outside git, every file except under .git, .rewindagents, .venv, __pycache__, node_modules, venv.
  • symlinks, directoriesSymlinks are not saved. Directories created by later steps stay, empty, after a rewind.
  • the end of the logA hash chain proves the records are unchanged relative to each other. It cannot tell that records were cut off the end or that the whole file was rewritten and re-hashed. Pin the head hash somewhere the agent cannot write and check against it with verify --head.

09Commands

Six commands. All of them local.

Run them from the project directory, the one holding .rewindagents/. They work on the latest session unless you pass --session ID.

Replay, rewind, branch

branch N --name X keeps the current files and, in a git repository, commits the whole working tree to rewindagents/X through a temporary index, so your HEAD, index and current branch stay as they were.

# one line per step: number, tool, file or command
$ rewindagents replay
# step 12 in full: input, checkpoints, result
$ rewindagents replay --step 12
# what would change
$ rewindagents rewind 12 --dry-run
# the same files, as a unified diff: now -> step 12
$ rewindagents diff 12
# only that file (a directory means every file under it)
$ rewindagents diff 12 src/db.py
# files back to how they were right after step 12
$ rewindagents rewind 12
# put back only these
$ rewindagents rewind 12 --only src/db.py --only tests/
# what taking back step 12 alone would change
$ rewindagents revert 12 --dry-run
# take back step 12 alone, keep every later step and hand edit
$ rewindagents revert 12
# keep the current files, then rewind to step 12
$ rewindagents branch 12 --name try2

Export a replay

One HTML file with every step, its input and result, and for every file a step touched, the change that step made as a unified diff. Inline CSS only, no scripts, nothing fetched, the project's path not in the page. A file over 256 KB is described, not diffed; a diff longer than 400 lines is cut, with the count left out.

# writes .rewindagents/replay-<session>.html
$ rewindagents export
# a given session, to a given file
$ rewindagents export --session abc --out replay.html
# steps, tools and paths only: no inputs, results or diffs
$ rewindagents export --no-contents
# keep secrets as recorded (they are replaced by default)
$ rewindagents export --no-redact

Find a session

One line per session: id, first and last time, steps (with how many are rewinds), files touched. The latest session is marked. --grep keeps the sessions with a step whose command, file or input mentions the text, and lists those steps with their numbers.

# every session in the log: id, first and last time, steps, files touched
$ rewindagents sessions
# only sessions with a step that mentions it, and those steps
$ rewindagents sessions --grep config.py

Verify the chain

Checks every record against the one before it and names the first bad one. With --head, also catches records cut from the end.

$ rewindagents verify --head <pinned-hash>

11Questions

Questions.

Does it stop or change what the agent does?

No. The hook records and checkpoints, then exits 0. It has no opinion about any call. The agent runs exactly as it would without the hook; the difference is that afterwards every step is on record and every file change can be put back.

Does anything leave my machine?

No. rewindagents makes no outbound network connections: a test checks that no module under src/ imports socket, http or urllib, except the timeline UI, which serves rewindagents ui on 127.0.0.1 only and checks a one-time token on every request. The log and the file copies live in .rewindagents/ inside your project, and nothing reads them but you.

Which agents does it work with?

Claude Code, through its PreToolUse and PostToolUse hooks; Codex, through the same hook file shape in .codex/hooks.json; Cursor, through .cursor/hooks.json; and Gemini CLI, Copilot CLI, Droid and Qwen Code, each through its own project hook file (the docs page names them). The Claude Code, Codex and Cursor hooks were verified in a live session on 2026-11-18, and so were the Gemini CLI and Copilot CLI hooks. The Codex and Cursor hooks are also tested with the payloads in the vendors' hook documentation. The Droid and Qwen Code hooks are tested with the documented payloads, not yet in a live session; the README says the same.

Does it need git?

No. Recording, replay and rewind work in any directory. Git changes two things: around Bash commands the scan follows git ls-files, so git-ignored files are left alone, and branch commits the current files to a git branch. Outside git, branch keeps them in the log only.

What happens if the log is tampered with?

verify names the first record that does not match the one before it, rewind changes nothing, and export still writes the page, with a notice naming the bad record, and exits 1. Records cut off the end are only caught against a pinned head hash.

Is it free?

Yes, under Apache-2.0: the recorder, the hook, replay, rewind, branch, export and sessions. A paid Cloud tier is planned and nothing is sold before it exists.
