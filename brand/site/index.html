Rewind your coding agent to any step.

Ctrl+Z for AI coding agents: record, replay, rewind. rewindagents saves each file before the agent changes it and logs every tool call. When a session goes wrong, put the project back the way it was at any step, in one command, within the limits below.

02Install

Install, then add the hook to a project.

Python >=3.10. No dependencies beyond the standard library. Tested on Python 3.15 on macOS. Not on PyPI yet, so install from the repository. The docs walk through a first session.

Install

$ pipx install git+https://github.com/Johnbjoseph-cybersec/rewindagents
# or: pip install git+https://...
$ rewindagents --version

Or from a clone, pip install .. Without installing, PYTHONPATH=src python3 -m rewindagents runs the same CLI from a clone.

Add the hook

$ cd /path/to/your/project
# adds the hook to .claude/settings.json in this project
$ rewindagents install
$ rewindagents install --settings ~/.claude/settings.json
# or for every project
# adds the hook to .codex/hooks.json in this project
$ rewindagents install --agent codex
# adds the hook to .cursor/hooks.json in this project
$ rewindagents install --agent cursor
$ rewindagents install --agent cursor --settings ~/.cursor/hooks.json
# or for every project

install keeps everything already in the file and does nothing if the hook is already there. For Codex the file is .codex/hooks.json and for Cursor .cursor/hooks.json; those two hooks are tested with the payloads in the vendors' documentation, not yet in a live session. .rewindagents/ gets its own .gitignore, so the log and the copies stay out of your commits.

03How it works

Record. Checkpoint. Rewind.

A hook runs before and after every tool call the agent makes. It never stops a call and never changes one: it always exits 0, even when its own input is broken or the disk is full, and prints nothing but the one answer Cursor requires from a permission hook.

  1. Record

    Every call gets a pre record (tool and input) and a post record (tool and response) in .rewindagents/log.jsonl. Each record carries the SHA-256 of the one before it, so editing, deleting or reordering any record makes verify fail and name the first bad record. Appends are locked, so several processes can write to one log.

  2. Checkpoint

    Before Write, Edit, MultiEdit and NotebookEdit, the current bytes of the target file go to .rewindagents/objects/<sha256>. Around a Bash command, the project's files are saved first and scanned after, and only the files the command changed, created or deleted are checkpointed. Copies are stored by hash, so an unchanged file is stored once.

  3. Rewind

    rewind N puts back every file a later step changed and deletes the files later steps created. It first checks the hash chain and the hash of every stored copy; if the chain is broken it changes nothing. A rewind saves the current files and records itself as a new step, so a rewind is undone with another rewind.

04Limits

What it records, and where it stops.

The real behaviour and the real limit, from the code. rewind reports every file it could not put back and exits 1 if there was one.

  • 4,000 charactersA tool response longer than this is cut in the log, with its full length noted.
  • 20 MBA file over this size is noted and not copied, so it is reported and not restored.
  • 20,000 filesA project with more than this many files is not scanned around Bash commands. The call is still recorded, and rewind says the step was not scanned.
  • the project directoryOnly files inside it are scanned, saved or restored. In a git repository, the scan is what git ls-files --cached --others --exclude-standard lists: tracked and untracked files, not git-ignored ones. Outside git, every file except under .git, .rewindagents, .venv, __pycache__, node_modules, venv.
  • symlinks, directoriesSymlinks are not saved. Directories created by later steps stay, empty, after a rewind.
  • the end of the logA hash chain proves the records are unchanged relative to each other. It cannot tell that records were cut off the end or that the whole file was rewritten and re-hashed. Pin the head hash somewhere the agent cannot write and check against it with verify --head.

05Commands

Six commands. All of them local.

Run them from the project directory, the one holding .rewindagents/. They work on the latest session unless you pass --session ID.

Replay, rewind, branch

branch N --name X keeps the current files and, in a git repository, commits the whole working tree to rewindagents/X through a temporary index, so your HEAD, index and current branch stay as they were.

# one line per step: number, tool, file or command
$ rewindagents replay
# step 12 in full: input, checkpoints, result
$ rewindagents replay --step 12
# what would change
$ rewindagents rewind 12 --dry-run
# files back to how they were right after step 12
$ rewindagents rewind 12
# keep the current files, then rewind to step 12
$ rewindagents branch 12 --name try2

Export a replay

One HTML file with every step, its input and result, and for every file a step touched, the change that step made as a unified diff. Inline CSS only, no scripts, nothing fetched, the project's path not in the page. A file over 256 KB is described, not diffed; a diff longer than 400 lines is cut, with the count left out.

# writes .rewindagents/replay-<session>.html
$ rewindagents export
# a given session, to a given file
$ rewindagents export --session abc --out replay.html
# steps, tools and paths only: no inputs, results or diffs
$ rewindagents export --no-contents

Find a session

One line per session: id, first and last time, steps (with how many are rewinds), files touched. The latest session is marked. --grep keeps the sessions with a step whose command, file or input mentions the text, and lists those steps with their numbers.

# every session in the log: id, first and last time, steps, files touched
$ rewindagents sessions
# only sessions with a step that mentions it, and those steps
$ rewindagents sessions --grep config.py

Verify the chain

Checks every record against the one before it and names the first bad one. With --head, also catches records cut from the end.

$ rewindagents verify --head <pinned-hash>

07Questions

Questions.

Does it stop or change what the agent does?

No. The hook records and checkpoints, then exits 0. It has no opinion about any call. The agent runs exactly as it would without the hook; the difference is that afterwards every step is on record and every file change can be put back.

Does anything leave my machine?

No. rewindagents makes no network connections: a test checks that no module under src/ imports socket, http or urllib. The log and the file copies live in .rewindagents/ inside your project, and nothing reads them but you.

Which agents does it work with?

Claude Code, through its PreToolUse and PostToolUse hooks; Codex, through the same hook file shape in .codex/hooks.json; Cursor, through .cursor/hooks.json. The Claude Code hook has run in real sessions. The Codex and Cursor hooks are built from the vendors' hook documentation and tested with the documented payloads, not yet in a live session; the README says the same.

Does it need git?

No. Recording, replay and rewind work in any directory. Git changes two things: around Bash commands the scan follows git ls-files, so git-ignored files are left alone, and branch commits the current files to a git branch. Outside git, branch keeps them in the log only.

What happens if the log is tampered with?

verify names the first record that does not match the one before it, rewind changes nothing, and export still writes the page, with a notice naming the bad record, and exits 1. Records cut off the end are only caught against a pinned head hash.

Is it free?

Yes, under Apache-2.0: the recorder, the hook, replay, rewind, branch, export and sessions. A paid Cloud tier is planned and nothing is sold before it exists.
